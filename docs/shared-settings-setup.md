# Render 공유 설정 DB 연결

공유 범위: 쿠팡·네이버 API 인증 정보, 쿠팡·네이버 코드매칭표, ERP 공통 품목마스터, 플랫폼별 ERP 매핑, 품목 집계명·브랜드 보정값.
주문 원본, 재고 스냅샷, 업로드한 로켓그로스 엑셀, 조회 기간과 메뉴 고정 설정은 현재처럼 각 브라우저에 유지됩니다.

API 연결 설정의 열람·수정에만 공용 비밀번호를 사용합니다. 코드표·ERP 매핑은 사이트에 접속한 직원 누구나 수정할 수 있습니다. 일반 매출·주문 조회에는 비밀번호가 필요 없습니다. 로그인하지 않은 사용자에게 API 키는 반환하지 않고 서버에서 API 서명·네이버 토큰 처리를 수행합니다. 공용 비밀번호를 해제한 브라우저의 API 설정 화면에서는 키를 확인할 수 있습니다.

## 1. PostgreSQL 생성

1. Render Dashboard → **New → Postgres**.
2. DB 이름은 예를 들어 `sb-settings`. 기존 Web Service와 **같은 Region(현재 Oregon)** 에 생성합니다.
3. 계속 보관할 운영 데이터이므로 장기 유지·백업이 가능한 플랜을 선택합니다. 서비스와 DB에 필요한 비용은 Render에서 확인합니다.
4. 생성 후 DB의 **Internal Database URL**을 복사합니다. DB 주소·비밀번호는 채팅이나 소스코드에 올리지 않습니다.

이 저장소는 PostgreSQL용 일반 SQL과 `pg` 드라이버를 사용하므로 다른 PostgreSQL 서비스로도 옮길 수 있습니다. `DATABASE_URL`만 바꾸고 아래 암호화 키를 그대로 유지합니다. 내부 DB 주소를 사용할 경우 Web Service와 DB가 같은 네트워크에 있어야 합니다. 외부 DB는 해당 제공자의 인증서와 TLS 연결 옵션을 사용하고 인증서 검증을 끄지 않습니다.

## 2. Web Service 환경변수 3개 설정

Render → 현재 Web Service → **Environment → Add Environment Variable**.

| Key | Value |
| --- | --- |
| `DATABASE_URL` | 위 Internal Database URL |
| `SETTINGS_ENCRYPTION_KEY` | 아래 명령으로 생성한 64자리 16진수 키 |
| `WORKSPACE_PASSWORD_HASH` | 아래 비밀번호 도구가 출력한 bcrypt 해시 |

로컬 저장소 또는 Render Shell에서:

```sh
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
node scripts/hash-password.mjs
```

두 번째 명령은 비밀번호를 화면에 표시하지 않고 두 번 입력받습니다. 직원에게 알려줄 공용 비밀번호는 12자 이상, UTF-8 72바이트 이하입니다. 영문·숫자·기호 조합을 사용하세요. Render 환경변수에는 `WORKSPACE_PASSWORD_HASH=` 뒤의 해시만 붙여 넣습니다. `$`도 해시의 일부이며 따옴표는 추가하지 않습니다. Render가 `DATABASE_URL`을 제공하므로 환경변수는 로컬 `.env` 파일을 올리는 방식이 아닙니다.

**Save, rebuild, and deploy**를 실행합니다. Build Command `npm ci`, Start Command `npm start`는 그대로 사용합니다. 최초 DB 요청 시 `migrations/001-shared-settings.sql`이 자동 적용됩니다.

암호화 키는 AES-256-GCM으로 모든 공유 설정을 암호화하는 키입니다. 비밀번호 해시와 암호화 키를 회사 비밀관리 도구에 보관합니다. 키를 새 값으로 바꾸면 이전 DB 데이터를 복호화할 수 없습니다. 비밀번호를 변경할 때는 해시만 바꿔 재배포하면 되며 기존 API 설정 로그인 세션은 무효화됩니다.

세 변수 모두 없으면 기존 브라우저 방식으로 실행합니다. DB 모드의 연결·복호화가 실패하면 오류를 표시하고 브라우저 방식으로 자동 전환하지 않습니다.

## 3. 기존 데이터를 한 번 이관

반드시 **최신 코드표와 API 키가 저장된 기존 브라우저**에서 진행합니다. `onrender.com` 주소와 회사 도메인은 브라우저 저장 영역이 다르므로, 데이터가 저장된 동일한 사이트 주소로 접속하세요.

1. 사이트를 새로고침한 뒤 좌측 **API 연결 설정** 메뉴로 이동합니다.
2. **공유 데이터베이스** 영역에서 공용 비밀번호로 **API 설정 잠금 해제**.
3. **기존 브라우저 설정을 DB로 이관** 클릭.
4. 이관 완료와 **DB 저장 완료** 표시를 확인합니다. 성공 후 해당 브라우저의 이관된 localStorage 설정은 제거하며 이후 DB 값을 사용합니다. 주문·재고는 지우지 않습니다.
5. 다른 PC·브라우저로 접속해 코드표와 ERP 매핑이 같은지 확인합니다. API 설정은 잠겨 있고 일반 매출 조회는 가능합니다.

이관은 **DB 버전이 0인 최초 빈 상태에서만** 가능합니다. 다른 PC에서 먼저 코드표를 수정해 DB 저장이 시작되면 최초 이관을 실행할 수 없습니다. 처음 활성화한 직후에는 위 이관부터 완료하세요. DB가 비어 있고 기존 브라우저 설정이 있으면 자동 신규품목 발견 저장은 이관 전까지 보류합니다.

브라우저 저장 모드를 쓰던 다른 PC의 오래된 값은 DB를 자동으로 덮어쓰지 않습니다.

## 4. 저장·공유 동작 확인

- 코드표 수정 후 기존처럼 Enter 또는 다른 행 클릭으로 저장합니다. 우측 하단에 **DB 저장 중 → DB 저장 완료**가 표시됩니다.
- 다른 사용자의 변경은 약 3초 간격으로 확인합니다. 편집 중인 입력란이나 미저장 ERP 매핑이 있으면 적용을 보류하고 **최신 설정 적용**을 표시합니다.
- 동시에 수정하면 뒤늦은 저장은 버전 충돌로 차단합니다. **최신 설정 적용** 시 미저장된 변경은 JSON 파일로 내려받은 뒤 DB 값을 적용합니다. 필요한 변경을 다시 입력하세요. 이 파일에 API 설정 변경이 포함되면 API 키도 포함되므로 회사 내부에서 관리합니다.
- DB 장애 시 미저장 표시가 남고 자동 재시도합니다. 오류 상태에서 탭을 닫으면 미저장 변경은 사라질 수 있으므로 **DB 저장 완료**를 확인합니다.
- **API 설정 다시 잠그기**는 브라우저의 로그인 쿠키를 삭제하고 API 키 입력란을 비웁니다. 세션은 최대 12시간이며 HttpOnly·SameSite=Strict, HTTPS에서는 Secure 쿠키를 사용합니다.

이 구조는 직원들이 공유하는 단일 회사 워크스페이스입니다. 개인별 계정·수정자 감사기록·역할별 권한은 아직 포함하지 않습니다. 요청에 따라 코드표·ERP 매핑 수정에는 비밀번호를 요구하지 않으므로 사이트 접속 자체를 제한하려면 별도의 사내 접근제어를 추가해야 합니다.

## 5. 백업·DB 이전

DB와 **동일한 암호화 키**를 함께 보관합니다. PostgreSQL 기본 백업 도구를 그대로 사용할 수 있습니다.

```sh
# DB URL은 셸 환경변수로 설정하고 명령행에 비밀번호를 직접 적지 않습니다.
pg_dump --dbname="$DATABASE_URL" --format=custom --file=sb-settings.dump
pg_restore --dbname="$NEW_DATABASE_URL" --no-owner --no-acl sb-settings.dump
```

이전 시 저장 작업을 잠시 중단하고 새 DB에 복원한 뒤 Render의 `DATABASE_URL`만 변경해 재배포합니다. `SETTINGS_ENCRYPTION_KEY`는 변경하지 않습니다. 이미 데이터가 있는 대상 DB에는 자동 덮어쓰기하지 말고 별도의 빈 DB로 복원합니다. Render의 DB 백업 기능도 사용할 수 있습니다.

## 검증 범위

자동 테스트는 PostgreSQL 호환 메모리 엔진(pg-mem)에서 SQL 저장·재복원·버전 충돌·암호화, HTTP API의 공개/비밀번호 권한과 서버 서명을 확인합니다. 브라우저 두 개로 최초 이관·키 비공개·코드표 자동 공유·ERP 매핑 저장·잠금 해제를 확인했습니다. 운영 Render PostgreSQL 연결은 위 환경변수를 등록한 후 실제 사이트에서 최종 확인해야 합니다.
