마켓플레이스 매출 검수

매출내역의 SALE 상품 총 판매가(salePrice)에서 쿠팡지원·판매자·다운로드쿠폰을 차감한 합계와 같은 기간 구매확정 주문의 주문 금액(orderPrice) − 총 할인 금액(discountPrice)을 비교합니다. salePrice·saleAmount·쿠폰 금액을 대조해 이미 반영된 할인을 중복 차감하지 않습니다. 총 판매가가 없으면 saleAmount에 문서상 이미 반영된 쿠팡지원할인은 다시 빼지 않습니다. 반품은 별도 표시하며 배송비·수수료는 제외합니다. 매출인식일은 구매확정일 또는 배송완료 + 7일이어서 일자 차이가 날 수 있습니다. 매출내역은 어제까지만 조회하며 월별로 나눠 모든 페이지를 읽습니다.

주문 API는 주문일 검색입니다. 기본 14일 이전부터 조회하고 매출내역에 더 오래된 결제일이 있으면 자동으로 앞당깁니다. 공통 주문 데이터도 재사용합니다. ‘매출만’ 건이 남으면 주문 검색 시작일을 더 이전으로 설정하세요. 일치는 지정한 주문 검색 범위 내 검수 결과입니다.

플랫폼별 ERP 매핑 설정

고정값·원본 필드·코드표 조인·계산식을 선택하세요. 원본 필드는 한글명 · 영문명 · 원본 경로로 표시합니다. 날짜는 선택한 원본 값을 YYYYMMDD로 자동 변환합니다. 조인은 원본 키와 코드표 키가 정확히 하나 일치해야 합니다. 저장한 규칙은 현재 브라우저에서 적용되며 기존 설정은 기본값으로 들어 있습니다. ERP 첫 3개 헤더 행과 열 순서는 고정입니다.

계산식 도움말 · 예시

saleQuantity * weight 판매수량 × 코드표 가중치
ROUND(salesAmount / shippingQuantity, 2) 매출 ÷ 출고수량, 소수 둘째 자리 반올림
ROUND(salesAmount / 1.1, 0) 공급가
salesAmount - supplyAmount 부가세
erp.ISUG_AM 다른 ERP 열 참조

+, -, *, /, 괄호, ROUND(값, 0~6) 지원. 품목별로 마켓플레이스는 구매확정일, 그로스 API는 결제일 순으로 재고를 배부합니다. 그로스 엑셀은 개별 결제일이 없어 조회 종료일을 기준으로 합니다. 완성된 업로드는 플랫폼 → 출고일자 순으로 정렬합니다. LOT로 행이 나뉘면 출고·재고수량과 합계액을 나눠 보존하고 단가·세금을 다시 계산합니다. 원본 수량·가중치는 분할 전 값이며 shippingQuantity와 salesAmount는 분할 후 값입니다. LOT는 재고 자동 배부로 고정하고 만료·0 이하 재고는 제외합니다. 네이버는 상품번호 + 옵션관리코드 복합 키로 조인합니다. 배송비는 품번 10019·수량 1·LOT 및 프로젝트 공란으로 고정하고 나머지는 네이버 매핑을 따릅니다. 매출을 바꿔 원본 합계와 다르면 ERP 검수에서 다운로드가 차단됩니다.

파일을 여기로 드래그하세요.

윙 엑셀에는 일자별 데이터가 없습니다. 별도 파일 집계기간을 입력하지 않으며, ERP 생성 조건에서 선택한 기간의 종료일을 모든 엑셀 행의 출고일자·재고 배부 기준일로 사용합니다. TOTAL·합계·빈 행과 순판매금액/수량이 없거나 0인 행은 자동 제외합니다. 옵션ID와 순 판매 금액·순 판매 상품 수를 인식합니다. 순 수량이 없으면 전체-취소 수량, 그것도 없을 때 명시된 판매단가로만 정수 수량을 검증해 계산합니다.
