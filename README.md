# SB바이오팜 온라인 매출 집계 시스템

쿠팡 마켓플레이스 발주서와 로켓그로스 주문을 조회하고 제품별 수량 및 상품 매출을 비교하는 한국어 웹 앱입니다. Node.js 22 이상에서 실행하며, 엑셀 처리에는 고정 버전 ExcelJS를 사용합니다.

```sh
cd /workspace/superdrummer
npm ci
npm start
# 개발 중 자동 재시작: npm run dev
# 검증: npm test
```

기본 포트는 3000이며 `PORT`로 변경할 수 있습니다. 브라우저에서 서버에 접속해 **API 연결 설정**에 vendorId, Access Key, Secret Key를 입력하고 저장하세요. 원격 접속은 HTTPS가 필요합니다(Web Crypto 사용). localhost는 HTTP도 지원합니다.

## 사용법

- 마켓플레이스: 긴 기간을 선택하면 달력 월 경계로 나누어 각 구간을 최대 31일로 요청합니다. 예를 들어 1월 15일~4월 2일은 1월 15~31일, 2월, 3월, 4월 1~2일로 분할합니다. 각 월 구간의 6개 상태를 월 구간별로 상태를 순서대로 조회하고 모든 `nextToken`을 끝까지 따라갑니다. 화면 행 수에 상한을 두지 않습니다. 진행 상황과 페이지 수·캐시 수·고유 주문·배송 건수를 표시합니다.
- 대시보드와 주문 조회 모두 한 달력에서 시작일·종료일을 선택하며 31일 이상의 기간도 허용합니다. 월 이동 입력과 최근 3개월·최근 6개월·올해 바로가기를 제공합니다.
- 로켓그로스: 조회 시작일과 종료일을 지정하면 `/v2/providers/rg_open_api/apis/api/v1/vendors/{vendorId}/rg/orders` 목록 API를 호출합니다. `paidDateFrom`, `paidDateTo`는 `yyyymmdd`이며, 월 경계를 유지하되 31일인 월은 30일+1일로 나누어 조회합니다. 여러 달을 한 번에 선택할 수 있습니다. 각 구간의 `nextToken`을 끝까지 조회하고 이 탭의 로켓그로스 호출 시작 사이에 최소 1.25초 간격을 둡니다. 여러 탭/사용자의 합산 호출량은 별도로 관리해야 합니다. 출고일 이후 제공되는 주문만 포함됩니다.
- 조회 결과는 현재 탭 메모리에 누적되고 페이지를 새로고침하면 삭제됩니다. 수신한 주문은 상품 행 전체를 교체해 중복 집계를 방지합니다. 실패한 조회는 전체를 반영하지 않습니다. 빈 결과는 기존 누적 데이터를 삭제하지 않습니다. 상태가 바뀌었거나 응답에서 사라진 주문까지 완전히 새로 집계하려면 **조회 데이터 비우기** 후 다시 조회하세요.
- **컬럼 선택 / 순서**는 좌측 전체 컬럼과 우측 선택 컬럼으로 구성됩니다. 양쪽 컬럼 앞 체크박스로 여러 컬럼을 선택하고, 각각 전체 선택·선택 해제를 할 수 있습니다. 가운데 → / ← 버튼 또는 왼쪽 파란 + / 오른쪽 빨간 휴지통으로 추가·제거합니다. 전체 선택은 검색된 컬럼에 적용됩니다. 표시 컬럼을 모두 제거해도 주문 데이터와 합계는 유지됩니다. 첫 번째 상품의 예시 값은 컬럼 옆에 표시됩니다. 우측 컬럼을 드래그하거나 위아래 버튼으로 순서를 바꾸고, 바깥 영역 클릭 또는 Esc로 닫을 수 있습니다. 원본 응답의 주문·상품 필드도 추가 컬럼으로 제공됩니다. 컬럼은 한글명과 작은 회색 원본 영문명을 함께 표시합니다. 선택과 순서는 마켓플레이스·로켓그로스별로 따로 브라우저에 저장됩니다. 컬럼 후보와 첫 데이터 예시는 해당 채널에서만 가져오며 로켓그로스에 없는 배송지·구매확정일·취소수량 컬럼은 노출하지 않습니다.
- 대시보드의 **매출 조회**는 지정 기간의 마켓플레이스 전체 6개 상태를 직접 조회하고, 같은 기간의 로켓그로스 주문 목록을 조회합니다. 모든 요청 성공 시 이번 결과로 기존 집계를 교체하므로 빈 응답이나 제외된 주문이 이전 총액에 남지 않습니다. 실패하면 기존 집계를 유지합니다. 주문번호를 입력할 필요가 없습니다.
- 주문 조회 결과는 대시보드에 즉시 반영되며, 마켓플레이스 조회 기간에 맞춰 대시보드 날짜 필터를 동기화합니다. 로켓그로스 조회도 동일하게 기간 필터를 동기화합니다. 주문 원본 표는 내부 스크롤 시 컬럼 헤더가 고정됩니다.
- 대시보드는 메모리에 조회된 주문을 사용하며 결제일, 통화와 상품 검색으로 범위를 조절합니다. 서로 다른 통화는 합산하지 않습니다. 제품은 브랜드, 용량, 생애주기·맛 등 옵션과 제품명 유사도를 비교해 채널과 옵션 ID를 넘어 묶어서 표시합니다. 원본 행과 옵션 ID는 그대로 유지합니다. 제품 검색은 제품 표에만 적용됩니다. 결제일 필터는 한국 시간으로 변환합니다. 로켓그로스 목록의 밀리초 타임스탬프를 한국 시간으로 변환하며 날짜 미확인 행은 날짜 필터 적용 시 제외됩니다.

## 집계 정의와 범위

- 마켓플레이스 수량: `max(0, shippingCount - cancelCount - holdCountForCancel)`. `canceled=true`는 0개.
- 로켓그로스 수량: `salesQuantity`, 단가: `unitSalesPrice`. 목록 응답의 `paidAt`은 밀리초 타임스탬프입니다.
- 상품 매출: 단가 × 위 수량. Money 타입의 `units + nanos / 1e9`를 반영합니다.
- 할인, 배송비, 수수료와 별도 반품 API의 정보는 반영하지 않습니다. 정산금액 또는 전체 판매실적이 아닙니다.
- 마켓플레이스는 선택 상태의 발주서, 로켓그로스는 목록 API에서 제공되는 출고 이후 주문만 포함합니다. 두 API의 모집단과 조회 범위가 다를 수 있습니다.

## 인증 및 중계

인증키는 사용자의 요청대로 localStorage에 저장합니다. 같은 출처의 JavaScript 또는 브라우저에 접근하는 사람이 읽을 수 있으므로 개인 기기에서 사용하고 필요하면 삭제하세요. 주문 개인정보는 저장소에 영구 저장하지 않습니다.

브라우저가 쿠팡 CEA HMAC-SHA256 서명을 생성합니다. Secret Key는 서버로 전송하지 않습니다. Access Key를 포함한 Authorization 서명은 같은 출처의 `/api/coupang`으로 전달되며 서버가 HTTPS 쿠팡 API에 GET 요청을 보냅니다. 키/인증 헤더 로깅은 하지 않습니다. 중계는 지정된 두 경로에만 허용하고 외부 출처 요청을 거부합니다. 공개 서비스로 운영하려면 사용자 접근 제어와 HTTPS를 배포 계층에서 구성하세요.

필요 네트워크 목적지는 `api-gateway.coupang.com`입니다. 실제 조회는 쿠팡 키 권한, 판매자 ID와 쿠팡 측 허용 IP 설정에 따라 제한될 수 있습니다. 이 저장소에는 실인증키가 포함되어 있지 않으며, 실제 계정의 응답 성공 여부는 미검증입니다.

## 제품명 분류와 실제 출고 수량

- `뉴앤힐`과 `뉴트리탑`의 공백·영문 표기를 통일합니다. `유한양행` 제조사 접두어는 제품명 비교에서 제외하므로 `유한양행 어덜트 뉴트리탑`도 뉴트리탑 브랜드에 포함됩니다.
- 사료·영양제·세정제는 상품명 및 제공된 원본 카테고리의 키워드로 추정합니다. 판별할 수 없는 브랜드·세분류는 미분류로 유지하며 모든 매출은 차트 합계에 포함합니다. 전문 상품 카탈로그에 기반한 확정 분류가 아닙니다.
- 명시된 `1개`, `3개`, `x3` 등의 묶음 수량을 인식합니다. `60정`, `100ml`, `30개입`은 용량으로 보존합니다. 실제 출고 수량은 취소 제외 주문 수량 × 묶음 수량입니다. 3개 묶음 1건이 30,000원에 팔리면 출고 수량은 3개, 매출은 30,000원입니다.
- 동일 브랜드·세분류·용량·맛·생애주기와 숫자 조건을 만족하는 이름만 비교합니다. 광고 문구·제조사 표기·묶음 수량·공백·단어 순서를 정규화하고 글자 2개 조합의 Dice 유사도 90% 이상을 같은 제품으로 취급합니다. 12자 이상인 긴 이름은 글자 편집 유사도 94% 이상이며 최대 3자 차이인 경우도 묶습니다. 짧은 이름은 정규화 후 일치하는 경우만 합칩니다. 실제 이름에 따라 오인식할 수 있습니다.
- 제품 표의 **원본·분류 확인**에서 옵션별 원본 상품명, 주문 수량, 인식한 묶음 수량을 확인하고 브랜드·세분류·묶음 수량을 교정할 수 있습니다. 교정 규칙만 이 브라우저의 `sb-product-overrides`에 저장됩니다. 원본 주문 데이터와 API 수량·금액은 수정하지 않습니다.
- 세분류·브랜드 선택은 대시보드의 카드, 차트, 제품 표 전체에 적용됩니다. 제품명 검색은 제품 표에만 적용됩니다. 금액과 점유율은 선택 통화 및 같은 결제일 모집단을 사용합니다.

## 차트와 주문 합계

- 채널별·항목별·브랜드별 매출을 같은 한 줄의 원형 차트로 비교합니다(좁은 화면에서는 세로 배치). 각 차트 하단 표는 분류명·금액·점유율 순서이며 같은 결제일·통화 모집단으로 계산합니다. 브랜드별 색상은 분류 필터를 바꿔도 유지합니다.
- 제품별 판매 실적의 판매 채널 필터는 제품 표에만 적용됩니다. 브랜드·항목을 상품명 앞에 표시하며, 내부 스크롤 시 헤더가 고정됩니다.
- 주문 조회는 표시 주문/전체 주문 건수, 표시 상품 행 수, 취소 제외 수량 합계, 통화별 상품 매출 합계를 제공합니다. 채널·검색 필터와 합계가 같은 모집단을 사용합니다. 표 하단에도 수량·금액 합계가 고정됩니다. 원시 단가 자체를 합산하지 않습니다.
- API 응답의 안전한 정수 범위를 넘는 숫자 ID는 문자열로 파싱하여 19자리 배송번호의 정밀도를 보존합니다. 원본 영문 경로와 값도 정확한 ID를 표시합니다.
- 전체 발주서 조회도 API가 제공하는 선택 기간·상태의 결과에 한정됩니다. 별도 반품/취소 API, 쿠팡 정산 내역 또는 전체 과거 주문을 대체하지 않습니다. 실제 계정과의 주문 건수 차이는 조회 조건과 원본 응답을 비교해야 확정할 수 있습니다.

## 주간·월간 추이 및 비교

- 전체 매출 추이에서 주별/월별을 전환합니다. 주는 한국 날짜의 월요일~일요일이고, 월은 달력 월입니다. 첫·마지막 구간은 선택한 날짜 범위로 잘립니다. 양 채널을 조회한 범위의 빈 구간은 0으로 채우지만 미조회 구간은 선을 끊어 구분합니다. 선 그래프의 기간별 금액 보기를 열어 정확한 수치를 확인할 수 있습니다.
- 별도 **주간 비교현황**과 **월간 비교현황**에서 기준 날짜/월을 선택하고 조회합니다. 주간은 이전 주, 월간은 이전 달과 비교합니다. 진행 중인 주는 오늘까지 집계하고 이전 주도 가능한 같은 경과 일수로 맞춥니다. 월간은 선택 월이 진행 중이어도 지난달 전체를 비교 대상으로 사용합니다. 완료된 달은 각각 전체 달을 비교하므로 28/30/31일 차이가 있습니다. 두 기간의 실제 날짜를 항상 표시합니다.
- 비교 화면은 이전·선택 기간의 매출, 증감액, 증감률과 연속 추이, 채널·항목·브랜드·상품별 매출·가중 수량 증감 표를 제공합니다. 주간 그래프는 이전 주부터 선택 주까지 일별로 한 줄을 이어 기간별 색을 구분하고, 월간 그래프는 이전 월부터 선택 월까지 주별로 한 줄로 표시합니다. 증감 표는 전체 폭으로 한 개씩 세로 배치합니다. 진행 중인 기간의 증감 비교 범위와 연속 추이의 전체 날짜 범위는 다를 수 있으며 화면에 명시합니다. 상품 묶음·유사 이름은 양 기간을 합친 공통 분류로 비교하므로 옵션명이 달라도 동일 제품의 증감을 볼 수 있습니다. 이전 매출이 0이고 선택 매출이 발생하면 무한 증감률 대신 ‘신규’로 표시합니다.
- 비교 탭은 두 기간을 직접 조회한 별도 메모리 데이터를 사용합니다. 비교되지 않은 기간을 0으로 가정하지 않습니다. 대시보드의 조회 데이터나 날짜·채널 필터를 덮어쓰지 않으며, 통화도 별도로 선택합니다.

## 조회 성능과 캐시

- 이전의 일별 × 상태별 호출을 월 구간 × 상태별 호출로 줄였습니다. 빈 결과 기준 한 달 최대 31×6=186회 대신 기본 6회이며 페이지가 늘어나면 추가 요청합니다. 양 채널은 동시에 불러오고 마켓플레이스의 월 구간·상태는 순서대로 처리합니다. 마켓 호출 간 최소 250ms 간격을 두어 한 달의 모든 상태·페이지를 완료한 후 다음 달로 진행합니다. 로켓그로스는 기존 1.25초 호출 간격을 유지합니다.
- 성공한 API 구간은 현재 탭 메모리에 5분 동안 캐시하며 대시보드·주문 조회·비교 탭에서 같은 구간 요청에 재사용합니다. 오류·부분 페이지 결과는 캐시하지 않습니다. 판매자 또는 인증 정보가 바뀌면 캐시를 비웁니다. 키나 주문 응답을 캐시 목적으로 디스크에 저장하지 않습니다.
- 상단 **조회 방식 → 최신 데이터 다시 받기**는 캐시를 건너뜁니다. 화면에 실제 API 요청 수·캐시 재사용 구간 수·걸린 시간을 표시합니다. 5분 이내 재사용 결과는 실시간 최신 값과 다를 수 있습니다.
- 한 채널이 실패하면 이번 두 채널 조회/비교 결과는 반영하지 않고 기존 결과를 유지합니다. 완료한 성공 구간의 캐시는 재시도에 재사용할 수 있습니다.

## ERP 업로드 양식 생성

1. 사용자 요청에 따라 38개 옵션 코드표가 기본 제공됩니다. 기존 브라우저 수정값을 우선하며 실제 재고는 포함하지 않습니다. 초기 JSON 가져오기도 지원합니다. 재고는 즉시 브라우저에 저장됩니다. 이후 **ERP 생성 메뉴 안의 재고 업데이트**에서 최신 ERP 표를 붙여넣으면 자동 저장·전체 교체되며 기준일 입력은 없습니다.
2. API 주문은 대시보드/주문 조회 또는 ERP 생성의 **선택 기간 API 주문 불러오기**로 확보합니다. 일반판매는 확보한 주문 중 `orderItems.confirmDate`가 생성 기간에 속하는 구매확정 건만 출력합니다. 주문 조회 API의 검색일과 구매확정일은 다르므로 이 기능이 전체 구매확정 이력을 자동 보장하지는 않습니다.
3. 그로스 취소를 반영하려면 **로켓그로스 엑셀 업로드**에서 드래그 또는 파일 선택으로 XLSX/CSV/TSV를 가져오고 실제 파일의 집계 기간을 입력한 뒤 적용합니다. XLSX 다중 시트, 앞쪽 설명·빈 행을 지원합니다. 구형 XLS 파일은 XLSX로 저장해야 합니다.
4. **ERP 업로드 양식 생성**에서 API 데이터 적용 또는 엑셀 데이터 적용을 선택합니다. 엑셀 모드에서도 일반판매는 API 데이터를 사용하며, 그로스만 순판매 엑셀로 교체합니다. ERP 기간은 그로스 엑셀의 집계 기간과 정확히 같아야 합니다.
5. **코드 매칭 · LOT 배부 · 검수**를 실행합니다. 플랫폼별 양식 `합계액` SUM과 대상 원본 매출 SUM이 일치하고 모든 행 검증이 통과해야 XLSX 다운로드가 가능합니다. 오류 시 정상 일부 행도 다운로드하지 않습니다.

### 매칭·수량·금액

- 사용자 제공 코드표 38개 옵션은 기본 제공하며 실제 재고 수치는 포함하지 않습니다. 옵션ID 문자열을 정확히 조인해 품번·품명·브랜드·프로젝트코드·프로젝트·본품여부·가중치를 부여합니다. 이름 유사도나 상품ID로 대신 매칭하지 않습니다. 이어케어 옵션 `95774573584`의 가중치는 사용자 확인에 따라 3으로 정정했습니다. 코드표 전체 붙여넣기 교체와 옵션별 가중치 수정은 브라우저에 저장됩니다.
- 출고수량/재고단위수량은 취소·환불대기 제외 주문 수량 × 코드표 가중치입니다. 매출에 가중치를 다시 곱하지 않습니다. API 그로스 수량은 `salesQuantity`를 사용합니다. 없을 때는 응답에 명시된 `salesAmount`와 판매단가가 있고 나눗셈이 정수로 확인될 때만 대체합니다. 이를 확인할 수 없으면 오류로 남기고 순판매 엑셀을 사용하도록 안내합니다.
- 일반판매 원본 매출은 `orderPrice - discountPrice`를 취소 제외 수량 비율로 배분합니다. `orderPrice`가 없으면 단가×원 주문 수량을 사용합니다. 할인·부분 취소별 실제 정산 차이는 원본 API와 대조가 필요합니다. 그로스 엑셀은 순 판매 금액/순 판매 상품 수를 사용하며, 없으면 전체 거래-총 취소 필드로 계산합니다. 명시된 판매단가가 있을 때만 수량 대체 계산을 허용합니다.
- 일반판매는 고객 `867`, 장소 `7110`, 구매확정일자, 비고 ‘쿠팡일반판매 구매확정건’, 주문자/수취인 이름을 사용합니다. 그로스는 고객 `8378700664`, 장소 `7120`, 선택한 기간의 종료일, 비고 ‘로켓그로스 판매건’을 사용합니다.
- 거래구분 0, KRW, 환율 1, 과세구분 0, 단가구분 1, 창고 7000, 관리구분 100이 기본값입니다. 담당자코드는 사용자 규칙대로 공란이고 필요하면 입력할 수 있습니다. 주문번호 등 명시된 공란 필드는 공란으로 유지합니다. API의 긴 주문번호는 별도 검수 화면에만 표시합니다.
- 부가세포함단가=해당 배부 행 금액/출고수량(소수 둘째 자리 반올림), 공급가=해당 행 금액/1.1(원 단위 반올림), 부가세=합계액-공급가입니다. 정수 기반 반올림과 잔액 배분으로 LOT 분할 시 수량·총매출을 보존합니다. KRW 이외 통화는 이 ERP 양식 생성에서 차단합니다.

### 재고 클립보드와 LOT 배부

- 실제 브라우저 `paste` 이벤트의 `text/html`, `text/plain`, 공개 JSON MIME 데이터를 읽습니다. 직접 읽기 버튼은 사용자 동작으로 Clipboard API를 사용합니다. HTML 표의 병합 셀(rowspan/colspan), 탭 텍스트, CSV 인용 필드, 공개 JSON의 열 이름/필드키 매핑을 지원합니다. 실제 ERP가 브라우저에 공개하지 않은 내부 메모리나 전용 클립보드 포맷은 읽지 못하며, 이때 공개된 형식 이름과 오류를 표시합니다.
- 창고코드·장소코드·품번·LOT No(또는 LOT번호)·기말재고만 필수입니다. 기초재고·입고·출고가 없어도 오류로 보지 않습니다. 기말재고의 천 단위 쉼표와 소수점을 인식합니다. 같은 창고·장소·품번·LOT 중복은 임의 합산하지 않고 오류로 표시합니다.
- LOT는 우측 8자리 유통기한을 해석하고 **유통기한이 빠른 순(FEFO)**으로 사용합니다. 동일 유통기한은 원본 재고 표 순서입니다. 입고일 데이터가 없으므로 실제 입고일 FIFO를 증명하지는 않습니다. 출고일 기준 만료/날짜 해석 불가 LOT와 다른 창고·장소의 재고는 사용하지 않습니다.
- 부족한 재고, 미매칭 코드, 날짜·필수값·길이·금액 오류와 검수 불일치는 출력 차단 사유입니다. 재고 기준일을 따로 입력하지 않으며 저장된 기말재고를 배부 기준으로 사용합니다. 재고의 실제 재반영 여부는 ERP 운영 과정에서 확인해야 합니다.
- 배부는 스냅샷 사본에서 수행하며 생성/다운로드를 반복해도 원본 기말재고를 차감하지 않습니다. 다운로드만으로 ERP에 전표가 등록되거나 업로드 성공이 확인되지 않습니다. 같은 파일을 ERP에 중복 업로드하지 않도록 실제 등록 이력은 ERP에서 확인해야 합니다.

### 출력 파일 및 보관

- 실제 OOXML `.xlsx` 파일의 첫 행은 35개 한글 컬럼명, 둘째 행은 ERP 영문 코드, 셋째 행은 타입·길이·필수·설명 문자열입니다. 데이터는 넷째 행부터이며 컬럼 추가나 앞쪽 안내 행을 넣지 않습니다. 문자 코드·YYYYMMDD 날짜는 문자열, 수량·단가·공급가·부가세·합계액은 숫자로 저장합니다.
- ExcelJS 브라우저 번들은 같은 출처 `/vendor/exceljs.min.js`에서 필요한 시점에만 불러옵니다. 원본 파일과 클립보드 내용은 서버에 업로드하지 않습니다. 코드표·재고·그로스 순판매 데이터는 이 브라우저 localStorage에 저장됩니다. 주문정보를 포함한 API 데이터는 판매자별 IndexedDB에 보관하여 메뉴 간 재사용하며 전체 조회 데이터 삭제로 지울 수 있습니다. 인증키는 공통 데이터 저장소에 넣지 않습니다.
- 자동 검증은 모의 API, 브라우저 클립보드 이벤트, 실제 XLSX 생성·재열기까지 수행합니다. 사용 중인 ERP의 실제 클립보드 형식과 ERP 서버의 파일 수입 수락 여부는 별도 현장 검증이 필요합니다.

## 화면·품목마스터·조회 개선

- 컬럼 선택 창의 왼쪽 전체 목록은 원본 필드 발견 순서를 별도로 보관해 표시합니다. 오른쪽 표시 순서를 바꿔도 왼쪽 순서는 바뀌지 않습니다. 플러스는 SVG 아이콘으로 중앙 정렬합니다. 오른쪽은 포인터로 드래그하는 동안 실제 행을 옮기고, 가장자리에서 자동 스크롤하며 놓을 때 순서를 저장합니다.
- 재고 업데이트는 별도 메뉴 대신 ERP 메뉴의 작은 접이식 패널에 있습니다. 정상 붙여넣기·클립보드 읽기·텍스트 업데이트 즉시 브라우저에 저장하고, 기초/입고/출고 및 재고 기준일을 요구하지 않습니다. 0 이하 기말재고는 저장·표시에서 제외합니다. 삭제와 현재 탭에서의 삭제 되돌리기를 제공합니다. 헤더만 있거나 인식 오류가 있으면 기존 재고를 유지합니다.
- 품목마스터에서 옵션ID별 집계 명칭·브랜드·항목을 지정하면 대시보드와 주간/월간 비교의 동일 상품 분류에 공통 적용됩니다. 명칭을 바꿔도 묶음 수량은 원본명에서 인식합니다. ERP 품번·코드표와 원본 API 값은 변경하지 않습니다. 초기화하면 자동 분류로 돌아갑니다. 사용자 선택에 따라 품목마스터와 재고/컬럼 설정은 서버가 아닌 현재 브라우저에 저장합니다.
- 대시보드 추이와 월간 주별 추이의 각 포인트 위에 매출·직전 포인트 대비 증감액·증감률을 표시합니다. 첫 포인트는 비교 없음, 이전 금액 0에서 매출이 발생하면 신규로 표시합니다. 미조회 포인트는 증감을 계산하지 않습니다. 포인트가 많으면 수치가 겹치지 않도록 그래프 영역을 가로 스크롤합니다.
- 0원 미분류는 항목 차트에서 숨깁니다. 비교 표에서는 양 기간 모두 0일 때 숨겨, 이전 미분류 매출이 사라진 증감 내역은 보존합니다. 제품 표의 브랜드·항목은 색상 배지로 구분합니다. 증감 표 헤더와 숫자의 크기·대비를 높였습니다.
- 읽기 API의 네트워크 오류·429·502·503·504는 최대 3회 시도합니다. 대기 간격과 `Retry-After`를 반영하며 인증/요청 오류(400·401·403)는 반복하지 않습니다. 페이지를 끝까지 받은 성공 구간만 캐시합니다. 자동 재시도 중에도 토큰과 조회 범위는 그대로 유지하며, 로그 없이 UI에 재시도 상황을 표시합니다. 실제 계정의 첫 실패 원인은 별도 응답 로그 확인이 필요합니다.

- 공통 조회 저장소는 채널·상태별 완료 기간을 보관하고 부족한 날짜 구간만 추가 호출합니다. 최신 데이터 다시 받기는 해당 기간을 교체하며 빈 응답도 반영합니다. 기본 재사용은 과거 조회 시점 자료이므로 상태·취소 변경을 반영하려면 최신 조회를 사용하세요. 주간·월간 선택 기간도 브라우저에 보관합니다.
- 컬럼 드래그는 포인터 이벤트를 사용하여 브라우저의 반투명 드래그 복제본을 띄우지 않습니다. 잡았던 위치에 옅은 자리 표시를 남기고 놓을 때 제거합니다.


### 마켓플레이스 매출 검수

- `GET /v2/providers/openapi/apis/api/v1/revenue-history`를 같은 출처 서명 프록시로 호출합니다. 판매자 ID, `recognitionDateFrom/To`, 첫 페이지 `token=`, `maxPerPage=50`을 전달하며 월 경계/31일로 나누고 `hasNext`와 `nextToken`을 끝까지 확인합니다. 반복·누락 토큰이나 잘못된 응답은 완료 처리하지 않습니다. 어제까지만 조회합니다.
- 기본 비교는 매출내역 `SALE`의 `items[].saleAmount`와 기존 ERP 기준의 구매확정일·취소 제외·할인 반영 주문 매출입니다. 수량이 반영된 총금액이므로 다시 수량을 곱하지 않습니다. 배송비·수수료·정산금액은 비교에서 제외합니다. `REFUND`는 `-abs(saleAmount)`로 별도 합산하여 순매출도 보여줍니다. 0원인 주문/옵션 0의 조정용 행은 제외하며, 실제 조정 금액은 포함합니다.
- 주문번호+옵션 ID로 금액과 누락을 대사합니다. 총합이 같아도 서로 다른 주문에서 차이가 상쇄되면 일치로 표시하지 않습니다. 일자별 합계와 구매확정일 없음 등의 제외 내역도 확인할 수 있습니다.
- 주문 API 검색은 주문일 기준입니다. 기본 90일 이전부터 검색하고 매출내역에 더 이른 결제일이 있으면 앞당깁니다. 공통 주문 데이터의 미조회 구간만 조회하며 헤더의 최신 조회를 선택하면 다시 받습니다. 일치는 지정한 주문 검색 범위 내 결과이며, 주문 API 미제공 건·배송완료+7일과 구매확정일 차이·반품·할인 정의 차이는 실제 데이터에서 확인해야 합니다. 검수 상세는 현재 판매자와 기간을 표시하여 브라우저 localStorage에 보관하며 삭제할 수 있습니다.

### ERP 매핑 설정

- 마켓플레이스 / 로켓그로스 API / 로켓그로스 엑셀별 기존 규칙을 기본 제공하고 `sb-erp-mapping-v1`에 저장합니다. 저장한 규칙은 실제 ERP 생성에 적용됩니다. 저장 전 수정은 실행에 영향을 주지 않으며, 변경 후 기존 생성 결과의 다운로드는 다시 생성할 때까지 차단합니다.
- 35개 출력 열마다 공란·고정값·원본 필드·코드표 조인·계산식·재고 LOT를 설정합니다. 조인의 원본 키, 코드표 키, 출력 열을 선택할 수 있으며 정확히 하나가 매칭되어야 합니다. 기본 조인은 옵션ID→코드표 옵션ID입니다. 수량은 기본 `saleQuantity * weight`, 단가는 `ROUND(salesAmount / shippingQuantity, 2)`입니다.
- 계산식은 숫자·필드·사칙연산·괄호·`ROUND(값, 0~6)`만 지원하는 파서로 실행합니다. JavaScript나 임의 코드는 실행하지 않습니다. `erp.영문컬럼` 참조와 순환 참조 검사를 지원합니다. 출고일은 `issueDate`로 YYYYMMDD 변환값을 선택할 수 있습니다.
- 출고수량·재고단위수량·합계액은 분할 전 규칙으로 평가한 뒤 LOT별로 배부합니다. 다른 계산식에서 `shippingQuantity`, `salesAmount`, `erp.SO_QT` 등은 배부 후 수량/금액을 참조합니다. 실제 소수 금액을 보존하고 필수값·길이·정밀도를 검사합니다. 매핑으로 매출을 바꿔 원본 합계와 다르면 기존 대사에서 다운로드를 막습니다.
- LOT는 재고 배부로 고정하며 유통기한순 또는 재고 입력순을 선택할 수 있습니다. 창고·장소·품번·만료·양수 기말재고 조건은 모두 적용합니다. ERP 첫 3개 헤더 행과 출력 열 순서는 바꾸지 않습니다. 기본값 복구와 첫 상품 예시를 제공합니다. 실제 ERP 업로드 수락 여부는 운영 환경 확인이 필요합니다.
