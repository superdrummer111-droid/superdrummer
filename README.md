# SB바이오팜 온라인 매출 집계 시스템

쿠팡 마켓플레이스·로켓그로스와 네이버 스마트스토어 주문을 조회하고, 매출 집계·비교·검수 및 ERP 출고 엑셀을 생성하는 한국어 웹 앱입니다.

## 실행

Node.js 22 이상이 필요합니다.

```sh
npm ci
npm start
# 개발: npm run dev
# 검증: npm test
```

기본 포트는 3000이며 `PORT`로 변경할 수 있습니다. Render에서는 `npm ci` / `npm start`를 사용합니다. HTTPS 배포가 필요하며 localhost는 HTTP도 지원합니다. 런타임 의존성은 ExcelJS 4.4.0, bcryptjs 3.0.2, pg 8.16.3으로 고정합니다.

## API 연결과 조회

**API 연결 설정**에서 채널별 키를 입력합니다. 저장한 인증 정보가 있는 채널을 대시보드·주간·월간에서 함께 조회합니다. 주문 조회는 선택한 채널만 조회합니다.

- 쿠팡: vendorId, Access Key, Secret Key. 브라우저에서 CEA HMAC-SHA256 서명을 생성하므로 브라우저 모드에서는 Secret Key를 서버로 전송하지 않으며, DB 모드에서는 서버에 암호화해 저장하고 서버에서 서명합니다. 서버는 허용된 주문·매출내역 경로만 GET으로 중계합니다.
- 네이버: 커머스 API 애플리케이션 ID(Client ID), Secret(Client Secret). 자체 스토어는 판매자 ID를 비워 SELF로 사용하며, 대행 연동 시 판매자 ID로 SELLER를 사용합니다. 연결 확인 버튼은 토큰 발급을 검사하며 주문 권한은 실제 조회 시 검사합니다.
- 네이버는 서버에서 `clientId_timestamp`를 Secret bcrypt salt로 서명하고 Base64 인코딩하여 `/external/v1/oauth2/token`에 요청합니다. 브라우저 모드에서는 키를 HTTPS 요청 처리 중에 사용합니다. DB 모드에서는 인증 정보를 암호화해 DB에 저장하고 접근 토큰을 서버 메모리에 보관합니다. 키·토큰은 로그에 남기지 않습니다.
- 주문은 `GET /external/v1/pay-order/seller/product-orders`를 사용합니다. 기간을 하루씩 나누어 `from`, `to`, `rangeType`, `page`, `pageSize=300`으로 요청하고 `pagination.hasNext`가 끝날 때까지 읽습니다. 결제일 조회와 구매확정일 조회 범위를 구분하여 재사용합니다. 주문번호 입력은 필요 없습니다.
- 마켓 주문은 달력 월별 최대 31일, 6개 상태를 순차 조회합니다. 그로스는 월별 최대 30일로 나누고 모든 nextToken을 읽습니다. 그로스 호출 간격은 최소 1.25초, 마켓은 250ms, 네이버는 500ms입니다. 네이버 주문은 최대 두 날짜를 동시에 처리하되 각 요청의 시작 간격을 직렬 제어해 호출 빈도를 유지합니다. 일시적인 실패는 자동 재시도합니다.
- 로딩 팝업은 마켓플레이스·로켓그로스·네이버 진행률을 각각 표시하고 조회 취소 버튼을 제공합니다. 취소 시 진행 중 요청과 재시도 대기를 중단하며 미완료 조회를 공통 데이터에 적용하지 않습니다. 진행 바는 완료 구간을 기준으로 진행률을 표시합니다. 전체 페이지 수를 미리 알 수 없으므로 조회·저장 완료 전에는 100%로 표시하지 않습니다.

운영 서버에서 필요한 목적지는 `api-gateway.coupang.com`, `api.commerce.naver.com`입니다. 쿠팡과 네이버 측의 API 권한·호출 서버 IP 허용 설정도 필요할 수 있습니다. 이 저장소에는 실제 인증키와 실제 고객 주문·재고 데이터가 없습니다. 실계정 인증·응답은 키를 입력한 운영 환경에서 확인해야 합니다.

## 저장과 원본 데이터

기본 모드에서는 API 키·코드표·ERP 품목마스터·설정을 브라우저 localStorage에, 조회한 주문 원본과 범위를 IndexedDB에 저장합니다. PostgreSQL을 연결하면 API 키·코드표·ERP 매핑·품목 보정값을 DB에 암호화해 공유합니다. API 설정만 공용 비밀번호로 보호하며 코드표·ERP 매핑은 비밀번호 없이 공유·수정합니다. 주문 원본·재고·로켓그로스 업로드와 조회 기간은 각 브라우저에 유지합니다. [Render DB 연결과 최초 이관 방법](docs/shared-settings-setup.md)을 참고하세요.

쿠팡 판매자별, 네이버 애플리케이션·판매자별로 데이터를 구분합니다. 같은 기간은 대시보드·현황·주문·ERP에서 공유하고 미조회 범위만 추가 요청합니다. **최신 데이터 다시 받기**는 해당 범위를 갱신하며 빈 응답도 기존 범위를 대체합니다. 요청 실패 시 전체 수신 결과를 반영하지 않습니다. API 호출 중 성공한 일부 응답은 재시도용 메모리 캐시에 재사용할 수 있습니다.

주문 조회는 원본 필드만 표시합니다. 금액 차감·단가×수량·units+nanos 합산을 하지 않습니다. 원본 수량·금액 열의 SUM만 통화별로 단순 합산합니다. 컬럼 선택·순서는 세 채널별로 독립 저장되며 해당 채널 원본 필드만 나옵니다. 체크박스·전체 선택·추가/삭제·즉시 드래그 재정렬·바깥 클릭 닫기를 지원합니다. 큰 정수 ID는 문자열로 보존합니다. **원본 엑셀 다운로드**는 현재 채널·기간·상태·검색 결과의 전체 행을 내보냅니다. 표시 컬럼(현재 순서) 또는 전체 실제 원본 컬럼을 선택할 수 있으며 1행은 한글명, 2행은 원본 필드 경로입니다. 할인·수량·타임스탬프를 계산/변환하지 않습니다. 긴 ID와 코드·앞자리 0은 문자로 보존하고 null은 문자열 null, 미제공 값은 빈 셀로 구분합니다. 배열은 원본 JSON으로 저장합니다. Excel 행 제한을 넘으면 시트를 나누고 셀 길이 제한 초과는 원본을 자르지 않고 오류로 알립니다.

## 집계 정의

- 마켓 상품 매출: `orderPrice − discountPrice`. 수량이나 부분취소 비율을 다시 곱하지 않습니다. 수량은 `shippingCount − cancelCount − holdCountForCancel`, 최소 0입니다. 상품 canceled 또는 명시적 주문 취소 상태는 계산 집계에서 제외합니다.
- 그로스: salesQuantity와 unitSalesPrice, 명시된 salesAmount가 있으면 이를 사용합니다. 수량 필드가 없을 때는 명시된 상품매출÷단가가 정수일 때만 대체합니다. 취소 API 지원 여부가 확인되지 않은 상태에서는 임의로 취소 필드를 차감하지 않습니다.
- 네이버: `productOrder.quantity`, `productOrder.totalPaymentAmount`를 사용합니다. CANCELED/CANCELLED는 집계상 0이고 원본 조회 값은 유지합니다. 네이버 수량에는 가중치를 적용하지 않습니다.
- 결제일 기준 대시보드·비교 현황은 상품 판매금액만 집계합니다. 네이버 배송비는 구매확정 매출 검수와 ERP에서 별도로 집계합니다. 정산예정액·수수료와 상품 매출을 혼용하지 않습니다.
- 쿠팡 코드표의 가중치만 쿠팡 수량에 적용합니다. 동일 ERP 품번은 세 채널을 합산하고 ERP 품목마스터의 품명·브랜드를 사용합니다. 구분별 그래프와 집계는 매출 내림차순이며 비교표는 선택 기간 매출 기준입니다. 시간 추이는 날짜 순서를 유지합니다. 원형 안에는 구분명·점유율만 표시하고 작은 조각은 바깥 라벨과 연결선으로 구분합니다. 총합계 금액은 원형 하단에, 항목 금액은 하단 표에 표시합니다. 브랜드 색은 주요 브랜드별 고대비 고정 색상을 사용합니다. 미매칭 상품은 원본 이름으로 남기며 코드표 관리에 미완료 행으로 추가합니다.
- 채널 색은 마켓 주황, 그로스 빨강, 네이버 녹색입니다. 항목·브랜드·채널의 꽉 찬 파이 그래프와 레이블 표, 제품 채널 필터, 고정 헤더를 제공합니다. 상품명 아래 원본 분류 편집은 제거하고 코드표/ERP 품목마스터에서 관리합니다.

## 주간·월간 비교와 경영진 보고

주간 집계는 **일주일 기준(일요일~토요일)** 또는 **보고일 기준(선택일 포함 직전 7일)**을 선택합니다. 진행 중인 주는 오늘까지 비교합니다. 월간은 지난달 전체와 선택 월의 오늘까지를 비교하며 지난달 일수를 잘라 맞추지 않습니다.

주간 일별·월간 주별 추이는 시간순 연속 한 선입니다. 월간 및 대시보드 추이 포인트는 금액·증감액·증감률을 표시합니다. 채널·항목·브랜드·상품 증감표는 금액과 수량을 함께 표시합니다.

**경영진 보고 형식** 탭에서는 쿠팡 두 채널을 COUPANG으로 묶고 NAVER와 비교하는 표, 전체 채널을 합친 표를 제공합니다. 브랜드 소계·플랫폼 소계·총합계를 포함합니다. 브랜드는 선택 기간 브랜드 매출 합계 순, 품목은 같은 브랜드 안에서 선택 기간 매출 순으로 정렬합니다. 반복 플랫폼·브랜드는 병합하고 감소액은 빨간색으로 표시합니다. 표별 **표 서식 복사**는 text/html과 text/plain을 함께 복사하여 Excel에 셀 병합·테두리·배경색·글자색을 전달합니다. 클립보드 쓰기가 제한되면 서식 복사 이벤트로 재시도하며 그래도 불가능하면 명확히 알립니다. **한 화면 보기**는 각 표를 창 크기에 맞춰 표시하며 Esc로 돌아갑니다. XLSX도 같은 병합·색상·정렬을 유지하며 시트별 한 페이지 인쇄를 지원합니다.

## ERP 작업 흐름

ERP 메뉴 안의 탭 순서는 재고 업데이트 → 그로스 엑셀 업로드 → ERP 업로드파일 생성 → 매출 검수 → 코드표 관리입니다. ERP 매핑 설정은 사이드바의 API 연결 설정 위에 있습니다.

1. **재고 업데이트**: ERP 웹 표를 복사해 붙여넣거나 클립보드 읽기를 사용합니다. text/html, text/plain, 일부 JSON 형식을 지원합니다. 합계·빈 행을 제외하고 기말재고만 사용합니다. 기초/입고/출고나 재고 기준일은 필수가 아닙니다. 성공 즉시 전체 교체·브라우저 저장하며 삭제·되돌리기를 지원합니다. 0 이하 재고는 배부하지 않습니다. 운영 재고는 기본 파일에 포함하지 않습니다.
2. **그로스 엑셀**: 13컬럼 순판매 XLSX·CSV·TSV를 드래그/선택합니다. TOTAL·빈 행·금액 또는 수량이 없거나 0인 행을 제외합니다. 엑셀 집계 기간과 ERP 기간은 같아야 하며 그로스 출고일자는 기간 종료일입니다. **로켓그로스 데이터 적용 방식**은 그로스에만 적용되며 마켓·네이버는 API를 사용합니다.
3. **코드표 관리**: 쿠팡 38옵션·네이버 97매칭을 기본 제공하며 기존 브라우저 수정값을 우선합니다. 네이버 소고기/오리 300g은 사용자 확인에 따라 AFS0304, 30g 샘플은 AFS0034입니다. 쿠팡은 옵션ID, 네이버는 상품번호+옵션관리코드로 정확히 조인합니다. 옵션이 없으면 빈 옵션코드끼리만 매칭합니다.
4. **ERP 품목마스터**: 공통 품번·품명·브랜드·프로젝트를 직접 수정/추가합니다. 각 채널 코드표의 품번/품명에서 검색 선택하면 관련 정보가 따라옵니다. 인라인 수정·행 추가·삭제·양식 다운로드·현재값 다운로드·엑셀 업로드를 지원합니다. 미매칭 항목은 빈 ERP 필드와 미완료 상태로 남습니다.
5. **ERP 생성**: 선택 기간 주문을 불러온 뒤 코드 매칭·LOT 배부·검수를 실행합니다. 마켓은 구매확정일, 네이버는 decisionDate가 기간에 속하는 건만 사용합니다. 마켓 주문 검색은 기본 14일 전까지 확장하지만 오래된 구매확정 건은 더 이전 주문 조회가 필요할 수 있습니다. 네이버는 구매확정일 범위를 직접 조회합니다.
6. 다운로드 XLSX는 정확한 35컬럼, 1행 한글명·2행 영문코드·3행 타입 설명, 4행부터 데이터입니다. 정수 숫자 형식은 `0`으로 설정해 `1.`을 만들지 않습니다. 소수는 필요한 자릿수만 표시합니다.

마켓 고객 867/장소7110, 그로스 고객8378700664/장소7120, 네이버 고객760/장소7110이 기본입니다. 네이버 담당자는900, 비고는 ‘네이버 구매확정건’, 내역은 주문자/수취인/주문번호입니다. 그로스는 기간 종료일, 마켓/네이버는 구매확정일로 출고합니다.

재고는 품목별 구매확정/결제일 순으로 배부합니다. 마켓과 네이버는 창고7000·장소7110의 같은 재고를 공유하므로 플랫폼별로 따로 차감하지 않습니다. LOT 우측8자리 유통기한이 빠른 순으로 사용하며 만료·유통기한 미확인·0 이하 재고를 제외합니다. 재고가 모자라거나 필수값/매칭 오류가 있으면 일부 행도 다운로드하지 않습니다. 배부 후 플랫폼→출고일자→품목 순으로 다시 정렬합니다. 다운로드 자체는 저장 재고를 차감하지 않습니다.

공급가·부가세·합계액은 정수 원 단위만 ERP에 출력합니다. 원본에 소수 금액이 있으면 임의로 버리지 않고 오류로 표시하며 다운로드를 막습니다. 단가는 소수 둘째 자리까지 허용합니다. 공급가=합계액/1.1 원 단위 반올림, 부가세=합계액−공급가, 부가세포함단가=합계액/출고수량 소수 둘째 자리 반올림입니다. LOT 분할 후에도 수량·총금액을 보존합니다. 재고단위수량 기본값은 출고수량과 같습니다. KRW만 ERP 출력합니다.

### 네이버 배송비

구매확정일이 존재하고 deliveryPolicyType이 ‘유료’인 주문에서 `deliveryFeeAmount`를 그대로 사용합니다. deliveryDiscountAmount는 다시 차감하지 않습니다. 주문번호별 가장 윗행을 기준으로 한 행만 생성하며 품번10019·수량1·재고단위수량1, LOT·프로젝트는 공란이고 재고 배부하지 않습니다. 나머지는 네이버 ERP 매핑을 따르며 공급가·부가세·단가는 상품과 같은 방식으로 계산합니다.

**매출 검수 → 네이버**에서 구매확정 상품 판매금액·주문별 배송비·합계를 별도로 표시합니다. ERP 생성 후에는 세 금액의 원본/양식 합계와 일치 여부를 각각 확인합니다. 배송비의 주문별 내역도 제공합니다.

### 마켓 매출 검수와 ERP 매핑

마켓 매출 검수는 revenue-history의 모든 페이지와 같은 기간 구매확정 주문을 대조합니다. 기본 주문 검색은 매출인식 시작일 14일 전이며 매출내역에 더 오래된 결제일이 있으면 앞당깁니다. 매출내역은 어제까지만 제공됩니다. 원본 salePrice·saleAmount·쿠팡지원/판매자/다운로드쿠폰을 비교해 이미 반영된 할인을 중복 차감하지 않습니다. API 필드 간 관계를 확정할 수 없으면 ‘원본 확인’으로 남깁니다. 반품·배송비·수수료는 분리합니다.

ERP 배부 후 마켓 매출 검수도 실행하고 간단한 합계 상태를 표시합니다. 외부 매출내역 검수가 불가능하면 미완료 경고를 남기며 기존 원본 주문↔ERP 금액 검수와 구분합니다. ERP 원본/양식 불일치와 매칭·재고 오류는 다운로드를 차단합니다.

ERP 매핑은 마켓/그로스API/그로스엑셀/네이버별로 고정값·원본 필드·코드표 조인·사칙연산·ROUND를 설정합니다. 원본 필드는 한글명·영문명·원본 경로로 표시합니다. 실행에는 eval을 사용하지 않으며 순환 참조·중복 조인·길이·숫자 정밀도를 검사합니다. 네이버 기본 조인은 상품번호+옵션관리코드 복합 키입니다. 저장 설정은 현재 브라우저에서만 적용합니다.

### 네이버 AFS0000 샘플 세트

AFS0000은 ERP 출고 시 AFS0031·AFS0032·AFS0033·AFS0034 네 실품목으로 분해합니다. 세트 주문수량마다 각 샘플 1개씩 출고하며 구성품별로 다른 일반 주문과 같은 재고를 공유해 구매확정 순으로 유통기한이 빠른 LOT부터 배부합니다. AFS0000 자체의 재고는 사용하지 않습니다.

세트 전체 판매금액을 4로 나눠 원 단위 반올림한 뒤 합계 차액은 AFS0031에 반영합니다. LOT가 나뉘어도 세트 원본 합계액과 원래 공급가(전체금액/1.1 반올림)·부가세 합계를 보존하도록 AFS0031의 공급가·부가세에서 최종 잔액을 조정합니다. 각 행의 공급가+부가세=합계액을 유지합니다. 한 구성품이라도 부족하거나 정수 차액을 AFS0031의 금액 범위 안에서 처리할 수 없으면 다운로드를 막습니다. 원본 API·매출 검수·대시보드는 분해 전 세트 금액을 유지하며 ERP 검수 내역에 세트 원품번을 표시합니다.

주문 조회의 로켓그로스 **선택 기간 전체 주문 상세**는 기간 목록에서 주문번호를 자동 수집하고 중복을 제거한 뒤 모든 상세 응답을 조회합니다. 주문번호 입력은 필요 없으며, 상세 결과는 선택 기간에 연결된 주문조회 화면 전용 데이터로 유지합니다. 상세 한 건이라도 실패하면 기존 표시 결과를 유지합니다.
